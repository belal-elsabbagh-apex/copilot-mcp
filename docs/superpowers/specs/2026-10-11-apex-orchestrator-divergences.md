# UiPath ↔ Apex Orchestrator Divergence Matrix

**Scope and method.** Appendix to `docs/superpowers/specs/2026-10-11-apex-orchestrator-integration-design.md`. Compares what copilot-mcp v1.33.1 does against UiPath Orchestrator (`src/uipath/`) with what the Apex orchestrator exposes. Four slices were reviewed: jobs, queues and transactions, logs/artifacts/faults, and platform. Apex evidence is GET-only and was collected live on 2026-10-11 against the prod Apex deployment (`orchestrator.apexmedicalai.com`, folders Authorization and Authorization Test); live responses were PHI-masked and no ids or token values are recorded here. Other Apex evidence comes from the dashboard JavaScript bundle and the Apex plugin v1.4.2 skill docs. UiPath evidence comes from copilot-mcp v1.33.1 source. Rows marked `[INFERENCE]` or listed under "Still unverified" were not observed.

## Contract-driving divergences

- Job state is renamed, not identical. Normalize to one enum and keep the raw backend status. Do not map UiPath `State` strings to Apex wire statuses by name.
- Terminal and in-flight sets differ. Apex has `claimed`, `cancelling`, `lost`, `timed_out`, `suspended`, and `resumed`. Use a per-backend `isTerminal`.
- Failure detail is Apex-only: `error_class`, `exit_code`, `outcome`, `needs_review`, `error_message`. UiPath returns null for these. Never fabricate them.
- Apex jobs can end without ever starting (`missing_credential`: `started_at`, `claimed_at`, `worker_id` null). Report `neverStarted` for terminal jobs with null `started_at`.
- Apex retry creates a new job on the same queue item (`attempt_number`, `retry_of_job_id`). Enumerate attempts by `reference=`. Apex `queue_item_id=` is silently ignored.
- Apex `/jobs` silently ignores unknown query params and returns the unfiltered total (279). Validate filter names client-side and verify with a known count.
- Apex list rows are thin. Failure text and `result_payload` need a detail GET.
- Apex has no RobotLogs API. Logs are one `job.log` artifact per job, whose footer is the real last line. The UiPath digest logic (`collapseLogs`, `findLogStalls`) needs a line parser and stall detection only covers NDJSON lines.
- Artifact listing needs `X-Folder-Id` outside the default folder (404 without it). Artifact download needs Bearer auth but no folder header, and supports `Range` (206).
- Identity: UiPath has numeric `Id` plus GUID `Key` (`stop_job` resolves Key→Id). Apex uses one UUID `id` for jobs, queues, and items.
- Queue items are addressed by `(queueId, itemId)` on Apex and by `fid` plus `QueueItems(<id>)` on UiPath. The adapter needs separate identity schemes.
- Order lookup: Apex per-queue `items?search=<orderUid>` matches (fuzzy; filter on exact `specific_content.orderUid`), and `items?reference=` matches exactly. Folder-wide only `/jobs?reference=` or `q=<reference>` match; `q=<orderUid>` does not. Canonical key: `orderUid` (resolution Q1).
- Payload typing differs. UiPath stringifies arrays inside `SpecificContent`. Apex items use native arrays, booleans, numbers, and objects. The builder and guard must emit the backend-specific shape.
- Write safety differs. UiPath has `z.literal("pre_prod")`, a domain assert, and `guardQueueItemSafety` (URL and placeholder checks). BE-built Apex items also carry `serverURL`, an SQS `queueUrl` and `token`, so the same URL checks apply; Apex adds a chokepoint gate because prod and test folders share one deployment and login.
- Environment binding: the host `orchestrator.apexmedicalai.com` is prod. Folder selects the environment: Authorization is prod, Authorization Test is test. The staging host shares the prod backend. Both folders currently hold only pre-prod-BE items. Bind host, folder, submit flag, and credentials as one env record.
- Folder naming: UiPath pre_prod is "Authorization Dev Clone". Apex pre_prod is "Authorization Test". Name drift must be config-driven, not hardcoded.
- Silent filter failure and paging caps differ. Apex `page_size` max is 200 (500 gives 422 with a pydantic `detail`). UiPath QueueItems `$top` max is 100 (errorCode 1009).
- Error shapes differ. Apex `detail` is a string (404, 403) or a pydantic list (422). UiPath uses OData errorCode. Normalize both.
